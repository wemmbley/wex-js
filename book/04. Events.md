# Обработка событий через шаблон

До этого момента мы вешали все обработчики событий в скрипте через `.on()`. 
Это основной и рекомендуемый способ в WEX. Но иногда удобнее объявить связь 
прямо в шаблоне — особенно когда элементов много и каждый должен вызывать 
свою функцию. Для этого существует директива `w-on`.

Главное что нужно понять: `w-on` не живёт без `fn`. Директива в шаблоне — это 
только половина, она лишь указывает имя функции. Саму функцию нужно 
зарегистрировать в скрипте через `.fn()`.

```html 
<template id="app">
    <input w-bind="message" placeholder="Введите сообщение">
    <button w-on="click:handleSubmit">Отправить</button>
    <p w-if="!!sent">Сообщение отправлено: {{ message }}</p>
</template>

<script>
    $('#app')
      .state({ message: '', sent: false })
      .fn('handleSubmit', state => function(e) {
          state.sent = true;
      })
      .mount()
</script>
```

Синтаксис `w-on="событие:имяФункции"` — событие это любое DOM-событие: 
`click`, `input`, `change`, `submit`, `keyup` и так далее.

## Несколько событий на разных элементах

Когда в шаблоне много интерактивных элементов, `w-on` позволяет держать связи 
прямо в разметке — не нужно угадывать по селектору в скрипте что к чему относится:

```html 
<template id="app">
    <input w-bind="query" w-on="input:onSearch" placeholder="Поиск...">
    <button w-on="click:onClear">Очистить</button>
    <button w-on="click:onSubmit">Найти</button>

    <p>Результат: {{ result }}</p>
</template>

<script>
    $('#app')
      .state({ query: '', result: '' })
      .fn('onSearch', state => function(e) {
          state.result = state.query.length > 0
              ? `Ищем: "${state.query}"`
              : '';
      })
      .fn('onClear', state => function(e) {
          state.query  = '';
          state.result = '';
      })
      .fn('onSubmit', state => function(e) {
          state.result = `Запрос отправлен: "${state.query}"`;
      })
      .mount()
</script>
```

## w-on внутри w-for

Особенно `w-on` раскрывается в списках — когда каждый элемент должен реагировать 
на событие со своими данными. Через `.fn()` в `state` уже доступен весь контекст:

```html 
<template id="app">
    <div w-for="item,index in cart traceby item.id">
        <span>{{ item.name }} — {{ item.qty }} шт.</span>
        <button w-on="click:onRemove">Удалить</button>
    </div>
    <p>Итого позиций: {{ cart.length }}</p>
</template>

<script>
    $('#app')
      .state({
          cart: [
              { id: 1, name: 'Хлеб',   qty: 2 },
              { id: 2, name: 'Молоко', qty: 1 },
              { id: 3, name: 'Сыр',    qty: 3 },
          ]
      })
      .fn('onRemove', state => function(e) {
          const btn   = $(this);
          const index = btn.closest('[w-for]').index();
          state.cart.splice(index, 1);
          this.update();
      })
      .mount()
</script>
```

Когда вы меняете массив методами вроде `splice`, `push` или `sort` — 
WEX не всегда замечает изменение автоматически. В таких случаях 
вызывайте `this.update()` вручную внутри функции — `this` внутри обработчика это сам `view`.

## Разница между w-on и .on()

| Описание различия | `w-on` в шаблоне     | `.on()` в скрипте        |
|------------------|--------------------|--------------------------|
| Где описана связь | прямо на элементе   | в скрипте по селектору   |
| Нужен ли `fn`    | обязательно         | нет, логика inline       |
| Удобно когда     | много разных кнопок | одно событие на группу    |
| Читаемость       | видно в шаблоне     | видно в скрипте          |

Оба подхода рабочие. Можно смешивать в одном приложении — никаких конфликтов нет.
