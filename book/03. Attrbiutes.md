# Атрибуты-директивы

Помимо биндинга и условного вывода, WEX предоставляет набор специальных атрибутов, 
которые управляют поведением и внешним видом элементов прямо из стейта. 
Все они работают по одному принципу: значение в стейте меняется — атрибут на элементе 
меняется автоматически. Не нужно руками лезть в DOM, писать `$('.btn').addClass(...) `
или `$('img').attr('src', ...)` — шаблон САМ за всем следит.

## w-value — значение поля из стейта

Устанавливает значение `input`, `textarea` или `select` односторонне — только из стейта в элемент. 
В отличие от `w-bind`, изменения пользователя обратно в стейт не летят.
Используется когда нужно просто отобразить данные в поле, не слушая ввод:
```html 
<template id="app">
    <input w-value="username" placeholder="Имя пользователя">
    <textarea w-value="bio"></textarea>
    <select w-value="role">
        <option value="admin">Администратор</option>
        <option value="user">Пользователь</option>
    </select>
</template>

<script>
    $('#app')
      .state({
          username: 'Алиса',
          bio: 'Люблю котиков и кофе.',
          role: 'admin'
      })
      .mount()
</script>
```

`w-value` — читает стейт и всё, ничего более. `w-bind` — читает и перезаписывает его обратно. 
Другими словами `w-value` иммутабельный ридер, в том время как `w-bind` мутабельный ридер-райтер.
Если нужна форма редактирования, берите `w-bind`. Если просто показать данные в поле — `w-value`.

## w-class — динамические классы

Позволяет добавлять и убирать CSS-классы в зависимости от условий стейта. 
По сути тот же `w-if`, только работает с классами. 
Принимает объект, где ключ — имя класса, значение — условие:
```html 
<template id="app">
    <button class="toggle-btn">Переключить</button>

    <div w-class="{ 'active': !!isActive, 'highlighted': score > 50 }">
        Этот блок меняет классы
    </div>

    <p>Очки: {{ score }}</p>
</template>

<script>
    $('#app')
      .state({ isActive: false, score: 75 })
      .on('click', '.toggle-btn', state => {
          state.isActive = !state.isActive;
      })
      .mount()
</script>
```

Класс active появится когда `isActive` станет `true`. Класс `highlighted` уже висит 
с самого начала — потому что score равен 75. Обычный атрибут `class` и `w-class`
прекрасно уживаются на одном элементе.

## w-disabled — блокировка элементов

Делает элемент недоступным для взаимодействия. Работает на `input`, `textarea`, `select` и `button`:
```html 
<template id="app">
    <input w-bind="email" placeholder="Email">
    <button class="submit-btn" w-disabled="!isValid">Отправить</button>
</template>

<script>
    $('#app')
      .state({ email: '', isValid: false })
      .on('input', 'input', state => {
          state.isValid = state.email.includes('@');
      })
      .mount()
</script>
```

Кнопка заблокирована до тех пор, пока пользователь не введёт корректный email. 
Никакого ручного `$('button').prop('disabled', true)` — стейт сам всем управляет.

## w-checked — чекбоксы и радиокнопки

Управляет состоянием checked у `input[type=checkbox]` и `input[type=radio]`:
```html 
<template id="app">
    <label>
        <input type="checkbox" w-checked="!!agree">
        Я согласен с условиями
    </label>

    <input type="radio" name="size" value="s" w-checked="size === 's'"> S
    <input type="radio" name="size" value="m" w-checked="size === 'm'"> M
    <input type="radio" name="size" value="l" w-checked="size === 'l'"> L

    <p w-if="!!agree">Размер выбран: {{ size }}</p>
</template>

<script>
    $('#app')
      .state({ agree: false, size: 'm' })
      .mount()
</script>
```

Для чекбокса — просто булевое значение. Для радиокнопок — сравнение 
текущего значения стейта с `value` конкретной кнопки. При монтировании `M` будет 
отмечен автоматически, потому что `size: 'm'`.

## w-selected — выбранный option

Управляет атрибутом `selected` у отдельных option внутри `select`. 
Удобно когда список опций генерируется через `w-for`:
```html 
<template id="app">
    <select>
        <option
            w-for="city in cities traceby city.id"
            w-selected="chosenId === city.id"
            w-value="city.id">
            {{ city.name }}
        </option>
    </select>

    <p>Выбран город с id: {{ chosenId }}</p>
</template>

<script>
    $('#app')
      .state({
          chosenId: 2,
          cities: [
              { id: 1, name: 'Париж' },
              { id: 2, name: 'Харьков' },
              { id: 3, name: 'Техас' },
          ]
      })
      .mount()
</script>
```

Харьков будет выбран по умолчанию — потому что `chosenId: 2` совпадает с его `id`.

## w-src — источник изображения

Устанавливает атрибут `src` у картинки из стейта. Всегда используйте `w-src` вместо 
обычного `src` когда путь к изображению динамический — иначе браузер попытается 
загрузить `src="{{avatarUrl}}"` буквально:

```html 
<template id="app">
    <div w-for="user in users traceby user.id">
        <img w-src="user.avatar" alt="Аватар">
        <span>{{ user.name }}</span>
    </div>
</template>

<script>
    $('#app')
      .state({
          users: [
              { id: 1, name: 'Алиса', avatar: '/images/alice.jpg' },
              { id: 2, name: 'Боб',   avatar: '/images/bob.jpg'   },
          ]
      })
      .mount()
</script>
```

## w-id — уникальный идентификатор узла

Присваивает виртуальному узлу стабильный внутренний идентификатор. 
WEX использует его при диффинге — чтобы точно понять какой DOM-элемент обновить, 
а какой не трогать:

```html 
<template id="app">
    <div w-for="msg in messages traceby msg.id">
        <div w-id="msg-{{msg.id}}" w-class="{ 'unread': !msg.read }">
            {{ msg.text }}
        </div>
    </div>
</template>

<script>
    $('#app')
      .state({
          messages: [
              { id: 1, text: 'Привет!',    read: true  },
              { id: 2, text: 'Как дела?',  read: false },
              { id: 3, text: 'Ответишь?',  read: false },
          ]
      })
      .mount()
</script>
```
`w-id` особенно полезен когда несколько однотипных блоков существуют рядом 
и нужно исключить путаницу при перерисовке. Значение должно быть стабильным 
и уникальным в пределах одного шаблона.
