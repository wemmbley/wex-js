# Хуки жизненного цикла
Любой компонент в WEX проходит через определённые этапы — появляется на странице, 
обновляется когда меняются данные, и в какой-то момент исчезает. 

Хуки — это способ встроиться в эти этапы и выполнить свой код в нужный момент.

Технически это обычный `.on()`, но вместо DOM-событий вроде `click` или 
`input` — специальные внутренние события, которые начинаются с `$`. 
WEX сам вызывает их в нужное время, вам остаётся только подписаться.

## $mount — компонент появился на странице

Срабатывает один раз, сразу после того как вью вставлена в DOM. 
Идеальное место для загрузки начальных данных, запросов к API или любой инициализации:

```html 
<template id="app">
    <div w-if="!!loading">Загрузка...</div>
    <div w-if="!loading">
        <p>Привет, {{ username }}!</p>
    </div>
</template>

<script>
    $('#app')
      .state({ username: '', loading: true })
      .on('$mount', state => {
          setTimeout(() => {
              state.username = 'Алиса';
              state.loading = false;
          }, 1500)
      })
      .mount()
</script>
```

Пользователь видит «Загрузка...» пока данные не пришли — затем 
WEX автоматически перерисовывает шаблон.

## $unmount — компонент убран со страницы

Срабатывает когда вы вызываете `view.unmount()`. Место для чистки — остановить таймеры, 
отписаться от внешних событий, сбросить что-то в исходное состояние:
```html 
<template id="timer">
    <p>Прошло секунд: {{ seconds }}</p>
    <button class="stop-btn">Остановить</button>
</template>

<script>
    let interval = null;

    const view = $('#timer')
      .state({ seconds: 0 })
      .on('$mount', state => {
          interval = setInterval(() => {
              state.seconds++;
          }, 1000);
      })
      .on('$unmount', state => {
          clearInterval(interval);
      })
      .on('click', '.stop-btn', state => {
          view.unmount();
      })
      .mount()
</script>
```
Без `$unmount` таймер продолжал бы тикать в фоне даже после исчезновения компонента.

## $change — стейт изменился

Срабатывает каждый раз когда любое значение в стейте меняется. 
Удобно для слежения за данными, логирования или синхронизации с внешними системами:
```html 
<template id="form">
    <input w-bind="query" placeholder="Введите запрос">
    <p>Символов: {{ length }}</p>
</template>

<script>
    $('#form')
      .state({ query: '', length: 0 })
      .on('$change', state => {
          state.length = state.query.length;
      })
      .mount()
</script>
```

⚠ Будьте осторожны — если внутри `$change` снова менять стейт, это вызовет ещё один `$change`. 
Следите чтобы не получилась бесконечная цепочка.

## $render — шаблон перерисован

Срабатывает после каждой перерисовки DOM. Нужен когда важно работать с реальными 
элементами уже после того как они появились или обновились — например 
инициализировать стороннюю библиотеку:

```html 
<template id="chart">
    <canvas class="my-canvas"></canvas>
</template>

<script>
    $('#chart')
      .state({ data: [10, 20, 30] })
      .on('$render', state => {
          // canvas уже в DOM, можно рисовать
          const canvas = document.querySelector('.my-canvas');
          // ... инициализация графика
      })
      .mount()
</script>
```

## $destroy — компонент уничтожен

Срабатывает при вызове view.destroy() — это жёстче чем unmount. 
Компонент не просто скрывается, а полностью удаляется вместе 
со всеми подписками. Используется для финальной очистки:

```js 
const view = $('#app')
  .state({ ... })
  .on('$destroy', state => {
      console.log('Компонент уничтожен, прощай')
      // финальная очистка, освобождение ресурсов
  })
  .mount()

// Где-то позже:
view.destroy()
```

## Вся цепочка жизни компонента
```
   .mount() вызван
      ↓
   $mount — компонент в DOM, можно инициализировать
      ↓
   стейт изменился
      ↓
   $change — данные обновились
      ↓
   $render — DOM перерисован
      ↓
   .unmount() вызван
      ↓
   $unmount — компонент ушёл, чистим за собой
      ↓
   .destroy() вызван
      ↓
   $destroy — всё, компонент больше не существует
```

## Сравнение хуков

| Хук        | Когда срабатывает                     | Типичное применение                                      |
|------------|--------------------------------------|----------------------------------------------------------|
| `$mount`   | Один раз, при появлении в DOM         | Загрузка данных, запросы                                 |
| `$change`  | При каждом изменении стейта           | Слежение, синхронизация                                  |
| `$render`  | После каждой перерисовки              | Работа со сторонними библиотеками                        |
| `$unmount` | При скрытии компонента                | Очистка таймеров, отписки                                |
| `$destroy` | При полном уничтожении                | Финальная очистка ресурсов                                |
| `$route`   | При смене роута                       | Когда нужен полный контроль роутинговой системы SPA      |
| `$wiring`  | При загрузке данных через `$wire()`   | Когда нужен полный контроль загрузки и обработки ошибок |
