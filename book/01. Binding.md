# Двойное связывание (он же биндинг)

Чтобы нам не приходилось вручную писать алгоритм связи вводимых пользователем данных
и нашего стейта, было придумано понятие биндинга. Двусторонний биндинг, это по сути
зависимость стейта от вводимых данных. То, что написано в инпуте, моментально 
летит в стейт, и то, что изменилось в стейте, моментально меняется в инпуте. 
По сути так и строится вся реактивность. Рассмотрим на примере. 

```html 
<template id="app">
    <input w-bind="mytext">
    <span>Вы ввели: {{ mytext }}</span>
</template>

<script>
    $('#app')
      .state({ mytext: '' })
      .mount()
</script>
```

Таким простым способом мы сделали реактивный вывод вводимых данных.

## Поддерживаемые элементы для биндинга

`w-bind` работает на трёх типах элементов — `input`, `textarea` и `select`. 
Принцип одинаков для всех: пользователь что-то выбирает или вводит — стейт обновляется мгновенно.

```html 
<template id="app">
    <input w-bind="name" placeholder="Имя">
    <textarea w-bind="comment" placeholder="Комментарий"></textarea>
    <select w-bind="city">
        <option value="kh">Харьков-Царь</option>
        <option value="odessa">Одесса-мама</option>
        <option value="kiev">Киев-Русь</option>
    </select>

    <p>Имя: {{ name }}</p>
    <p>Комментарий: {{ comment }}</p>
    <p>Город: {{ city }}</p>
</template>

<script>
    $('#app')
      .state({ name: '', comment: '', city: 'kh' })
      .mount()
</script>
```
⚠ `w-bind` — это именно двусторонняя связь. Если вы поменяете значение в стейте программно, 
инпут тоже обновится. Это отличает его от `w-value`, который работает только в одну сторону 
— из стейта в элемент.

## Предзаполненный стейт
Начальное значение в стейте автоматически попадёт в поле при монтировании. 
Удобно для форм редактирования:
```html 
<template id="app">
    <input w-bind="username">
    <span>Привет, {{ username }}!</span>
</template>

<script>
    $('#app')
      .state({ username: 'Рустам' })
      .mount()
</script>
```
Пользователь сразу увидит своё имя в поле и сможет его отредактировать — стейт 
подхватит изменения на лету. 

# Условный вывод

Иногда бывают ситуации необходимости вывести-скрыть определенный блок со страницы.
Имея под собой реактивность и стейт, а так же мощный шаблонизатор, это становится
рядовой и тривиальной задачей. Усложним предыдущий пример.

```html 
<template id="app">
    <input w-bind="mytext">
    <span>Вы ввели: {{ mytext }}</span>
    <div w-if="mytext === 'фильм'">
        Вы ввели слово фильм! Тайный блок открыт!
    </div>
</template>

<script>
    $('#app')
      .state({ mytext: '' })
      .mount()
</script>
```

## Как работает w-if

`w-if` принимает любое JavaScript-выражение, которое приводится к `true` или `false`. 
Если выражение истинно — элемент рендерится в DOM, если нет — его там просто нет.
Это важное отличие от простого CSS-скрытия: элемент не просто становится невидимым, 
он физически отсутствует в дереве до тех пор, пока условие не выполнится.

```html 
<template id="app">
    <input w-bind="age" placeholder="Введите возраст">

    <div w-if="age >= 18">
        Добро пожаловать!
    </div>
    <div w-if="age > 0 && age < 18">
        Доступ только с 18 лет.
    </div>
</template>

<script>
    $('#app')
      .state({ age: '' })
      .mount()
</script>
```

## Переключение по булевому флагу
Самый частый сценарий — показать или скрыть блок по кнопке. 
Для этого в стейте держим флаг и меняем его через `on`:
```html 
<template id="app">
    <button class="toggle-btn">Показать детали</button>

    <div w-if="!!isOpen">
        Здесь скрытые детали, которые видны только после нажатия.
    </div>
</template>

<script>
    $('#app')
      .state({ isOpen: false })
      .on('click', '.toggle-btn', state => {
          state.isOpen = !state.isOpen;
      })
      .mount()
</script>
```
`!!isOpen` — двойное отрицание явно приводит значение к булевому типу. 
Хорошая привычка, особенно когда в стейте могут оказаться `null` или `undefined`.

## w-if внутри w-for

`w-if` и `w-for` отлично уживаются вместе — можно фильтровать элементы списка прямо в шаблоне:
```html 
<template id="app">
    <div w-for="item,index in products traceby item.id">
        <div w-if="!!item.inStock">
            {{ index + 1 }}. {{ item.name }} — в наличии
        </div>
    </div>
</template>

<script>
    $('#app')
      .state({
          products: [
              { id: 1, name: 'Хлеб',   inStock: true  },
              { id: 2, name: 'Молоко', inStock: false },
              { id: 3, name: 'Сыр',    inStock: true  },
          ]
      })
      .mount()
</script>
```
Молоко не попадёт в DOM вовсе — только товары с `inStock: true`.

# Цикличный вывод

Порой нам надо динамически просмотреть стейт и вывести всё его состояние. Для этого 
в шаблоне реализована директива `w-for`, которая базово выглядит следующим образом:

```html 
<template id="app">
    <div class="list" w-for="listItem in list">
        <ul>
            <li>{{ listItem }}</li>
        </ul>
    </div>
</template>

<script>
    $('#app')
      .state({ list: ['privet', 'kak', 'dela'] })
      .mount()
</script>
```

Здесь происходит перебор значений из массива стейта и вывод их по заданному шаблону.

## Индекс элемента

Если помимо значения нужен порядковый номер элемента, достаточно добавить второй аргумент 
— без пробела между ними:

```html 
<template id="app">
    <div class="list" w-for="listItem,index in list">
        <ul>
            <li>{{ index + 1 }}. {{ listItem }}</li>
        </ul>
    </div>
</template>
```
⚠ Важно: `listItem,index` — без пробела внутри. `,index` необязателен.

## Traceby — отслеживание уникальных элементов

Когда список меняется (элементы добавляются, удаляются, перемещаются), 
WEX по умолчанию перерисовывает весь блок целиком. Это работает, но неэффективно — 
особенно если список большой или элементы содержат сложную вёрстку.

Traceby говорит фреймворку: «смотри не на позицию элемента, а на конкретное поле — 
и перерисовывай только то, что реально изменилось».

```html 
<template id="app">
    <div class="list" w-for="item,index in users traceby item.id">
        <ul>
            <li>{{ index + 1 }}. {{ item.name }}</li>
        </ul>
    </div>
</template>

<script>
    $('#app')
      .state({
          users: [
              { id: 1, name: 'Алиса' },
              { id: 2, name: 'Боб' },
              { id: 3, name: 'Вера' },
          ]
      })
      .mount()
</script>
```
Теперь если в массив добавится новый пользователь или один из них удалится — 
WEX не будет трогать узлы с уже знакомыми id. Это экономит ресурсы и исключает 
визуальные мигания при обновлении.

## Вывод обьектов
На практике `w-for` чаще всего работает не с плоскими строками, а с массивом объектов. 
Обращаться к полям можно напрямую через точку:
```html 
<template id="app">
    <div class="list" w-for="product,index in products traceby product.id">
        <ul>
            <li>{{ index + 1 }}. {{ product.name }} — {{ product.price }} ₽</li>
        </ul>
    </div>
</template>

<script>
    $('#app')
      .state({
          products: [
              { id: 1, name: 'Хлеб',   price: 45  },
              { id: 2, name: 'Молоко', price: 89  },
              { id: 3, name: 'Сыр',    price: 320 },
          ]
      })
      .mount()
</script>
```
