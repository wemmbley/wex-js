# Асинхронные компоненты

Когда приложение растёт, на одной странице может собраться десяток компонентов. 
Если грузить их все сразу — пользователь ждёт пока загрузится всё, даже то что ему 
сейчас не нужно. Модальное окно которое откроется только если нажать кнопку, редактор 
который появится только в режиме редактирования — зачем тащить их при первой загрузке?

Асинхронный компонент — это компонент который загружается только тогда когда действительно 
понадобился. Страница открывается быстро с минимумом кода, а тяжёлые части подгружаются 
по требованию в фоне.

## Простейший случай — ленивая загрузка модуля

Компонент живёт в отдельном JS-файле и загружается только когда страница его запрашивает:
```js 
// components/user-card.js — отдельный файл
export default $(`
    <template>
        <div class="user-card">
            <h3>{{ name }}</h3>
            <p>{{ email }}</p>
        </div>
    </template>
`)
  .state(() => ({ name: '', email: '' }))
```
```js 
// main.js — основной файл
const { createAsyncComponent } = window.jqvm

$('#app')
  .state({ user: { name: 'Алиса', email: 'alice@astre.ws' } })
  .component(
      'user-card',
      createAsyncComponent(() => import('./components/user-card.js'))
  )
  .mount()
```
```html 
<template id="app">
    <user-card :name="user.name" :email="user.email"></user-card>
</template>
```
Браузер загрузит `user-card.js` отдельным запросом — и только тогда когда шаблон 
встретит тег `<user-card>`. До этого момента файл не скачивается вовсе.

## Загрузка с индикатором — реальный сценарий

Асинхронная загрузка занимает время, и пользователь должен понимать что что-то происходит. 
Для этого у `createAsyncComponent` есть второй аргумент — `callback` который вызывается когда 
компонент загрузился:
```html 
<template id="app">
    <div w-if="!!loading" class="spinner">
        Загружаем редактор...
    </div>
    <rich-editor w-if="!loading"></rich-editor>
</template>

<script>
    const { createAsyncComponent } = window.jqvm

    $('#app')
        .state({ loading: true })
        .component(
            'rich-editor',
            createAsyncComponent(
                // loader — как загрузить компонент
                () => import('./components/rich-editor.js'),

                // callback — что сделать когда загрузился
                function() {
                    this.update({ loading: false })
                }
            )
        )
        .mount()
</script>
```
Пользователь видит спиннер пока компонент грузится. Как только загрузка завершилась 
— loading становится false, спиннер исчезает, редактор появляется.

## Загрузка HTML с сервера

Компонент не обязательно должен быть JS-модулем. Можно загрузить HTML прямо с сервера 
через Ajax — удобно когда шаблоны живут на бэкенде:

```js 
$('#app')
  .state({ loading: true })
  .component(
      'product-table',
      createAsyncComponent(
          // загружаем HTML через jQuery Ajax
          () => $.get('/components/product-table.html')
            .then((html) => {
                return $(html).vm(() => ({
                    products: [],
                    sortBy: 'name',
                }))
            }),

          function() {
              this.update({ loading: false })
          }
      )
  )
  .mount()
```

Сервер отдаёт кусок HTML, WEX оборачивает его в вью с нужным стейтом — и компонент готов. 
Это особенно хорошо сочетается с PHP и Blade: шаблоны хранятся на сервере, 
подгружаются по необходимости, данные приходят реактивно.

## Реальный кейс — тяжёлый редактор по клику

Самый частый сценарий применения — откладывать загрузку тяжёлых компонентов до момента 
когда пользователь явно их запросил:
```html 
<template id="app">
    <div w-if="!editorOpen">
        <p>{{ previewText }}</p>
        <button class="edit-btn">Редактировать</button>
    </div>

    <div w-if="!!editorOpen">
        <div w-if="!!editorLoading">Загружаем редактор...</div>
        <obsidian-editor w-if="!editorLoading"></obsidian-editor>
        <button class="cancel-btn">Отмена</button>
    </div>
</template>

<script>
    const { createAsyncComponent } = window.jqvm

    $('#app')
        .state({
            previewText: 'Нажмите редактировать чтобы изменить текст.',
            editorOpen: false,
            editorLoading: false,
        })
        .component(
            'obsidian-editor',
            createAsyncComponent(
                () => import('./components/obsidian-editor.js'),
                function() {
                    this.update({ editorLoading: false })
                }
            )
        )
        .on('click', '.edit-btn', state => {
            state.editorOpen   = true
            state.editorLoading = true
        })
        .on('click', '.cancel-btn', state => {
            state.editorOpen   = false
            state.editorLoading = false
        })
        .mount()
</script>
```

Пользователь открывает страницу — редактор даже не начинает загружаться. 
Нажал «Редактировать» — только тогда браузер идёт за файлом. 
Тяжёлые библиотеки не тормозят первую загрузку страницы.

## Когда использовать асинхронные компоненты

Не каждый компонент нужно делать асинхронным — это усложняет код и добавляет лишний 
сетевой запрос. Хорошие кандидаты:

Грузите асинхронно если компонент тяжёлый (редакторы, графики, карты), показывается 
не сразу (модалки, табы, аккордеоны) или нужен только части пользователей 
(формы редактирования, админские панели).

Грузите сразу если компонент маленький, нужен при первой загрузке или 
является частью основного интерфейса который пользователь видит всегда.

```
Маленькая кнопка, иконка           → обычный компонент
Шапка сайта, главное меню          → обычный компонент
Модальное окно                     → async
Текстовый редактор                 → async
Интерактивная карта                → async
Графики и дашборды                 → async
Форма которая открывается по клику → async
```

```
Асинхронные компоненты — это не оптимизация ради оптимизации. 
Это инструмент для конкретной задачи: сделать первую загрузку страницы быстрой, 
а тяжёлые части подтягивать только тогда когда они действительно нужны.
```
