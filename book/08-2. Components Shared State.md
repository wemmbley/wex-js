# Синхронизация компонентов между собой общим стейтом

Когда компонентов на странице становится больше одного, возникает естественный 
вопрос: а что если им нужно работать с одними и теми же данными?

Представьте корзину на сайте. Счётчик товаров в шапке, список товаров в боковой 
панели и итоговая сумма в футере — три разных компонента, но все они должны 
знать об одном и том же: что сейчас лежит в корзине. Если каждый хранит свою 
копию стейта — они начнут расходиться и показывать разное.

Store — это единый стейт который несколько компонентов разделяют между собой. 
Меняется значение в одном месте — все компоненты которые его используют 
обновляются одновременно автоматически.

## Как это работает

```js
// Создаём общий стейт — один на всех
const store = shareState({ count: 10 })

// Оба компонента получают один и тот же store вместо своего стейта
const componentA = $('<span>Значение: {{count}}</span>')
  .state(store)

const componentB = $('<div>count: {{count}}</div>')
  .state(store)
```

```html 
<template id="app">
    <comp-a></comp-a>
    <comp-b></comp-b>
</template>
```

```js 
$('#app').state({})
  .component('comp-a', componentA)
  .component('comp-b', componentB)
  .mount()
```

Оба компонента видят одно и то же count. Если count изменится — оба перерисуются.

## Реальный пример — счётчик корзины

Сделаем кнопку добавления товара и счётчик в шапке — два независимых 
компонента которые работают с одними данными:

```js
// Единый источник правды для всей страницы
const cartStore = shareState({
    itemCount: 0,
    total: 0,
})

// Шапка — только показывает
const cartBadge = $(`
    <template>
        <div class="cart-badge">
            🛒 <span>{{ itemCount }}</span>
        </div>
    </template>
`)
  .state(cartStore)

// Кнопка — только добавляет
const addToCart = $(`
    <template>
        <button class="add-btn">Добавить в корзину ({{ itemCount }})</button>
    </template>
`)
  .state(cartStore)
  .on('click', '.add-btn', state => {
      state.itemCount++
  })
```

```html 
<template id="app">
    <cart-badge></cart-badge>

    <main>
        <h2>Товар: Хлеб — 45 ₽</h2>
        <add-to-cart></add-to-cart>
    </main>
</template>

<script>
    $('#app').state({})
      .component('cart-badge', cartBadge)
      .component('add-to-cart', addToCart)
      .mount()
</script>
```

Нажали кнопку — itemCount вырос на единицу в cartStore — оба компонента мгновенно 
перерисовались с новым значением. Никакой передачи данных через пропсы, никаких 
событий наверх — просто общий стейт.

## Store + localStorage

Store прекрасно сочетается с механизмом storage который мы разбирали раньше. 
Достаточно добавить ключ storage в createStore — и общий стейт автоматически 
переживёт перезагрузку страницы:

```js 
const cartStore = shareState({
    storage: {
        itemCount: 0,
        total: 0,
    }
})
```

Теперь пользователь добавил товары, закрыл вкладку, вернулся — корзина на месте. 
И по-прежнему все компоненты синхронизированы между собой.

## Когда использовать Store, а когда пропсы

Не каждый стейт нужно выносить в Store. Хорошее правило:

Пропсы — когда данные принадлежат родителю и он осознанно передаёт их вниз. 
Например, родитель знает имя пользователя и передаёт его в дочерний компонент-приветствие.

Store — когда данные нужны нескольким компонентам которые не знают друг о друге и не имеют 
общего родителя. Корзина, авторизация, выбранная тема — всё что является глобальным 
состоянием приложения.

```
Локальный стейт    →  данные нужны только этому компоненту
Пропсы             →  родитель осознанно делится данными с ребёнком
Store              →  данные нужны нескольким несвязанным компонентам
```

``` 
Store это не серебряная пуля — не стоит тащить туда всё подряд. 
Если данные нужны только одному компоненту, пусть живут в его локальном стейте. 

Store появляется тогда, когда без него начинается неудобная передача данных 
через длинные цепочки пропсов или костыльные глобальные переменные.
```
