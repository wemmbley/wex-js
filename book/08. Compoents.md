# Компоненты

Если вы пришли из мира jQuery, скорее всего ваш код выглядит примерно так: 
большой HTML-файл, много $('.что-то').on(...), и всё в одном месте. 
Это работает — но когда проект растёт, один и тот же кусок разметки 
начинает копироваться по странице, а правка в одном месте требует правки 
во всех остальных.

Компонент — это переиспользуемый кусок шаблона со своим стейтом. 
Один раз описали карточку товара, кнопку или иконку — и вставляете их в 
любое место как обычный HTML-тег. WEX сам разберётся как это отрисовать.

## Первый компонент — иконка

Представьте что по всему сайту используются иконки, и каждый раз писать 
`<i class="icon icon-search"></i>` надоело. Вынесем это в компонент:

```js 
const { component } = window.jqvm

const icon = $(`<i class="icon icon-{{type}}"></i>`)
  .state(() => ({ type: 'eye' })) // начальное значение по умолчанию

component('icon', icon)
```

Теперь в любом шаблоне можно писать просто:
```html 
<template id="app">
    <icon type="search"></icon>
    <icon type="heart"></icon>
    <icon type="user"></icon>
</template>
```

WEX подставит нужный тип и каждый раз отрисует правильную иконку. 
Захотели изменить структуру иконки — меняете в одном месте, обновится везде.

```
Заметьте: в .state() передаётся функция, которая возвращает объект — 
а не сам объект напрямую. Это важно: каждый экземпляр компонента 
получает свою независимую копию стейта. Если передать объект напрямую — 
все иконки на странице будут делить один стейт и менять друг друга.
```

## Пропсы — передача данных внутрь

Пропсы это то что вы передаёте компоненту снаружи — как атрибуты HTML-тега. 
Есть три способа:

Обычная строка — просто пишете значение:
```html 
<icon type="search"></icon>
```
Выражение из стейта — ставите : перед именем, 
и WEX вычислит значение из текущего стейта родителя:
```html 
<icon :type="currentIcon"></icon>
<!-- currentIcon берётся из state родительского шаблона -->
```
Функция-обработчик — ставите @, чтобы компонент мог сообщить родителю о событии:
```html 
<my-button @click="handleClick"></my-button>
```

Важное ограничение: работают только те пропсы, которые объявлены в стейте компонента. 
Если в стейте компонента нет ключа color — передать color="red" снаружи не получится, 
атрибут просто проигнорируется.

```html 
// стейт компонента
.state(() => ({ type: 'eye', size: 'md' }))

// ✓ сработает — оба ключа есть в стейте
<icon type="search" size="lg"></icon>

// ✗ не сработает — color нет в стейте компонента
<icon type="search" color="red"></icon>
```

## Компонент карточки — реальный пример

Сделаем компонент карточки товара, который можно переиспользовать в каталоге:
```js 
const productCard = $(`
    <template>
        <div class="card">
            <img w-src="image" alt="Фото">
            <h3>{{ name }}</h3>
            <p>{{ price }} ₽</p>
            <button class="buy-btn">Купить</button>
        </div>
    </template>
`)
  .state(() => ({
      name: '',
      price: 0,
      image: '',
  }))
  .fn('buy', state => function(e) {
      alert(`Добавлено в корзину: ${state.name}`)
  })
  .on('click', '.buy-btn', function(state) {
      this.fn('buy')(state)
  })

component('product-card', productCard)
```

Используем в шаблоне через w-for:
```html 
<template id="catalog">
    <div class="catalog">
        <product-card
            w-for="item in products traceby item.id"
            :name="item.name"
            :price="item.price"
            :image="item.image">
        </product-card>
    </div>
</template>

<script>
    $('#catalog')
      .state({
          products: [
              { id: 1, name: 'Хлеб',   price: 45,  image: '/img/bread.jpg'  },
              { id: 2, name: 'Молоко', price: 89,  image: '/img/milk.jpg'   },
              { id: 3, name: 'Сыр',    price: 320, image: '/img/cheese.jpg' },
          ]
      })
      .mount()
</script>
```
Три карточки — три независимых компонента, каждый со своим стейтом.

## Эмиттер — компонент говорит с родителем

Пока что данные шли только в одну сторону: родитель передаёт пропсы — компонент 
их отображает. Но что если компонент хочет сообщить родителю что что-то произошло? 
Для этого есть `emit`.

Представьте компонент-счётчик, который должен уведомлять родителя об изменении значения:
```js 
const counter = $(`
    <template>
        <button class="minus-btn">−</button>
        <span>{{ count }}</span>
        <button class="plus-btn">+</button>
    </template>
`)
  .state(() => ({ count: 0 }))
  .on('click', '.plus-btn', state => function() {
      state.count++
      this.emit('change', state.count) // ← сообщаем родителю
  })
  .on('click', '.minus-btn', state => function() {
      state.count--
      this.emit('change', state.count) // ← сообщаем родителю
  })

component('counter', counter)
```
Родитель подписывается через `@change` и регистрирует обработчик через `.fn()`:
```html 
<template id="app">
    <counter @change="onCountChange"></counter>
    <p>Родитель знает: {{ total }}</p>
</template>

<script>
    $('#app')
      .state({ total: 0 })
      .fn('onCountChange', state => function(newCount) {
          state.total = newCount
      })
      .mount()
</script>
```
Компонент живёт своей жизнью внутри, но в нужный момент «кричит наружу» 
через `emit` — родитель слышит и реагирует.

## Локальный компонент vs глобальный

Если компонент нужен только в одном конкретном шаблоне — регистрируйте его 
локально через `.component()` прямо на вью. Если нужен по всему приложению — 
регистрируйте глобально через `component()` из импорта:

```js 
// Глобально — доступен везде
const { component } = window.jqvm
component('my-icon', icon)

// Локально — только для этого шаблона
$('#app')
  .state({ ... })
  .component('my-icon', icon) // ← метод самого вью
  .mount()
```

## Вся идея в одной строке

Компоненты в WEX — это те же самые вью, просто вложенные друг в друга. 
Всё что умеет обычный шаблон: стейт, директивы, хуки, `w-for`, `w-if` — 
всё это работает и внутри компонента. Никакого нового синтаксиса учить не нужно.
